## Context

filter_svc — единственный получатель сырья. Симуляции ходят текстом; сырьё
доставляется в filter изнутри shop_svc, минуя текстовый канал (инвариант 1).
Хранение — append-only: каждая запись под строкой хеш-цепочки `lab.chain`
(GENESIS → seq/prev/hash), перезапись payload детектируется.

## Goals / Non-Goals

Goals:

- сырьё + снимки + кассеты в одной БД, с проверяемой целостностью;
- наружу — только тексты: `/text/{episode_id}` не содержит raw-полей;
- `model_spec` пинится в каждой записи (инвариант 4).

Non-Goals:

- расчёт метрик в filter_svc (сбор ≠ расчёт, инвариант 7);
- пересоздание сырой БД между прогонами — она append-only.

## Decisions

- `raw.llm_calls` сериализуется кассетными строками `lab.cassette`: по строке
  на пару «запрос → ответ».
- Каналы записей: `legal` и `attack`; канал валидируется на входе.
- verify-эндпоинт отдаёт дефекты цепочки списком; пустой список — цепь цела.
