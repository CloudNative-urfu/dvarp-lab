## Context

shop_svc собирает перенесённые компоненты (БД, журнал, гвардрейлы, агент,
конфигурации, оценщик) в сервис с контрактами из `docs/api.md`. Ключевой
инвариант — барьер «только текст» (инвариант 1 мануала): ответ `/turn` —
ровно `{text, ended, session_status}`; сырьё уходит в `/record` filter_svc
изнутри (`_deliver`).

## Goals / Non-Goals

Goals:

- `/reset {seed}` — детерминированный сброс БД;
- `/configure {config_name, agent_model}` — применение конфигурации из
  frozen (номинальная проверка, иначе 400);
- `/turn` — ход агента поддержки: только текст наружу;
- снимки состояния: `GET /snapshot/{id}`, `POST /snapshot/restore` —
  основа парных прогонов.

Non-Goals:

- выдача решений гвардрейлов через API (только в сырьё);
- оркестрация эпизодов в shop_svc (это traffic/attack/launcher).

## Decisions

- Доставка сырья — `_deliver` изнутри обработчика /turn: поломка filter_svc
  фейл-клозит ход (эпизод не продолжается с потерянным сырьём).
- Снимок — полная копия логического состояния; restore возвращает БД в
  исходное состояние пары.
