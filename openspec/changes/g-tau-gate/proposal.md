## Why

G-τ — доля ложных прерываний легального трафика защитой (canon FR-1.22,
гейт ≤5% с Wilson 95% CI) — в лабе отсутствует: есть только detection
(TPR/FPR/precision), гейта нет. Операционное определение канона:
прерывание = исполненная политикой реакция isolate/escalate/terminate на
легальном эпизоде; clarify/flag не считаются; эскалация по явной просьбе
клиента — нормальное действие агента (не политика) и в G-τ не попадает.

## What Changes

- `services/metrics/formulas.py` — `wilson_ci` (95%), `G_TAU_THRESHOLD`
  (0.05), `G_TAU_INTERRUPT_ACTIONS`, `g_tau_gate` (pass/fail — помечается,
  не исключается из сравнения);
- `services/metrics/extract.py` — оракул-проверка `_false_interrupt` над
  событиями `policy.decision` в `raw.events` (исполненное действие, не
  предложенное); оракул-метка вида трафика — канал эпизода в raw DB
  (метка сбора); в `Aggregate`: G_tau_k/rate/Wilson/gate; E_L/E_A уже
  считаются (#12) — из того же источника (вердикты + канал);
- `services/metrics/app.py` — строки `G_tau_*` в выдаче;
- когда #10 (episode_finals) будет реализован, финалы будут нести
  `traffic_kind` напрямую — экстрактор перейдёт на них без смены формул.

## Capabilities

### Modified Capabilities
- `metrics-svc`: G-τ rate + Wilson 95% CI + гейт ≤5% считаются post-hoc
  поверх сырой БД (сбор ≠ расчёт).

## Impact

- Никакого нового сбора: оракул уже в данных (канал + события политики);
- канон не правится (операционное определение FR-1.22 совпадает с
  реализацией); issue #13 п. 3 — уточнений определения не потребовалось.
