## Context

Три сервиса падали на пустом старте: filter не создавал сырую БД до первой
записи, metrics читал несуществующий файл (500), shop нумеровал журналы
с нуля и конфликтовал с журналом прошлого запуска. Фикс — деградация:
пустые данные это валидное состояние (консоль, `/episodes`, «нет прогонов»).

## Goals / Non-Goals

Goals:

- сырая БД существует с момента старта filter_svc (append-only, не
  пересоздаётся);
- `/compute` и `/metrics/{config}` на отсутствующей сырой БД отвечают 200
  (пустой результат с note «нет прогонов»), а не 500;
- новый журнал ячейки — следующий номер после существующих
  (`journal-N.jsonl`), коллизия с непустым файлом — fail-closed
  (EventLogError), молчаливой перезаписи не бывает.

Non-Goals:

- пересоздание сырой БД при старте (она append-only);
- автоочистка журналов при рестарте.

## Decisions

- Номер журнала возобновляется: `max(existing) + 1` — рестарты dev-стека
  добавляют журналы; перезапись непустого журнала невозможна по построению.
- Метрики читают SQLite-файл только после проверки существования
  (in-memory URL всегда считается существующей).
