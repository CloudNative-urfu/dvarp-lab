## Why

Issue: https://github.com/CloudNative-urfu/dvarp-lab/issues/52 (остаток #4, «Дополнение владельца 2026-11-26»).

ИИ-агент desmitry не смог написать каталог атак (фильтр безопасности модели);
автор — тимлид в полном контексте исследования (авторизованный полигон,
защитное исследование). Постановка владельца: сразу все 70.

## What Changes

- `frozen/corpus/tactics.json`: 8 базовых методов + **62 новых** = 70; схема
  `dvarp.tactics/2` сохранена; приоритет семей — манипуляция суммой/количеством
  (доказанная брешь g0) и planted context;
- `frozen/corpus/darp_corpus_v3.jsonl` + `MANIFEST_v3.json`: 124 атакующие записи
  (atk-29…atk-152), прецедент ext-корпуса (файл + sha256 + хеши записей; вне
  рантайм-загрузчика `load_corpus()`);
- тесты: состав реестра (70, покрытие 1…152), манифест v3 ↔ jsonl fail-closed,
  иллюстрация ↔ запись 1:1.

## Capabilities

### Modified Capabilities
- `attack-methods-registry`: реестр методов расширен каталогом v3 до 70.

## Impact

- оси методов (launcher/UI/CLI) подхватывают 70 имён из frozen; имена базовых
  методов не менялись — старые спеки кампаний работают;
- калибровка на живой LLM — следующий шаг #4 (desmitry, локальный стенд):
  метод остаётся при приросте V(g0), слабые переписываются.
