## Why

Проверка работоспособности LLM-контура (прокси, доступность моделей, живой
промпт) требует иногда выходить за локальные эндпоинты — но данные статьи
должны остаться строго локальными (NFR-2.4/2.5). Нужен явный флаг обхода
локальности с тройным guard-ом в данных, чтобы remote-прогоны никогда
случайно не попали в датасет статьи.

## What Changes

- флаг `allow_remote_llm` (спека осей / CLI `--allow-remote-llm`, галочка в
  UI) — обход локальности эндпоинтов только для проверки;
- `lab/nominal.py` — допускает remote-эндпоинты только с флагом;
- пин в манифесте прогона (`remote_llm: true`) и в записях
  (`raw.remote_llm=true`);
- `metrics_svc` — remote-эпизоды исключены по умолчанию; `include_remote` —
  явная опция `/compute`;
- `tests/test_remote_llm.py` — тройной guard.

## Capabilities

### New Capabilities
- `remote-llm`: флаг allow_remote_llm и тройной guard (манифест, записи,
  метрики) для remote-верификации контура.
