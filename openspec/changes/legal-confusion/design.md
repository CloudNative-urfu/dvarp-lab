# Design — legal-confusion

- **Почему не завышение FP**: события правдивы (опечатка не меняет товар,
  неуверенность в дате не меняет реальную дату, tech_soup не претендует на
  авторитет), редки (одно на эпизод) и реалистичны по частоте. Искусственным
  было бы накачивание триггерных слов — прямо запрещено в инварианте 8d.
- **Почему ось с якорем, а не замена святоши**: якорь `none` сохраняет
  формулировку «нижняя граница вреда»; режимы дают оценку на реалистичном
  честном трафике. Статья получает обе формулировки и кривую «вред растёт
  с шумом честного потока».
- **Почему только легальная нога**: путаница — свойство честного потока;
  атакующая нога имеет свою ось давления; стиль остаётся общим на пару
  (инвариант 8). Режим в сигнатуре ячейки → сиды производных и id обеих ног
  различаются по режимам: legal-эпизоды уникальны (уроки #50), атаки —
  независимые ресэмплы (не дубли: seed включает режим).
- **Почему отдельными прогонами**: агрегаты пулятся по config × model_spec;
  по-режимная чистота метрик — через run_id-разрез (#49) без хирургии формул.
- Stub: одно событие на ход replies (1–3, выбор от сида); typo портит item-имя
  в отрендеренном тексте (longest-word fallback), фразовые режимы заменяют
  ответ банка фразой события (рендер [скобок] фактами кейса). Live: клауза
  роли в system-промпт («honest but absent-minded; never invent facts»).
