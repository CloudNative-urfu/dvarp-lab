## Context

Код защиты (гвардрейлы, агент, журнал, оценщик) переносится из
dvarp-prototype @ `d5828df` как есть — адаптируется только клей (каналы,
порт-глю, нейминг импортов). Подсистемы прототипа report_cli, isolation,
svckit, state_store, pay_emu, runner+replay, freeze-машинерия и
Next.js-консоль не переносятся сознательно: полигону нужен сбор и расчёт,
а не продуктовая обвязка.

## Goals / Non-Goals

Goals:

- один репозиторий, читаемый как схема: каждый сервис — один `app.py` плюс
  узкие пакеты, обмен только JSON по HTTP на локальных портах;
- замороженные характеристики исследования в `frozen/` — конфигурации защиты
  (26 файлов + `configs.lock.json`), корпус атак, ростер моделей, стили;
- openspec-трейс с первого коммита: дельта спеки — в том же коммите, что и код;
- тесты pytest как единственная автоматическая проверка кода.

Non-Goals:

- Dockerfile, CI-workflows, quality-gates, мутационные скрипты — не создаются;
- переработка перенесённого кода защиты (только адаптация клея).

## Decisions

- `lab.chain` — единственная реализация хеш-цепочки (JSONL, seq/prev/hash,
  `verify()` возвращает список дефектов); на ней строятся журнал shop и
  сырая БД filter. Обрезка хвоста по построению не обнаружима — это
  crash-safe свойство, не баг (инвариант 5 мануала).
- `lab.cassette` — по строке на пару «запрос → ответ» к модели; любой вызов
  модели в любом сервисе обязан оседать кассетой (инвариант 6).
- `lab.modelspec` — ростер `frozen/llm.json`; пин модели
  `ModelSpec(name, role, params_b, revision)` входит в каждую запись
  (инвариант 4).
- `lab.nominal.check_config` — номинальная проверка конфигурации перед
  прогоном: конфиг из frozen, LLM-эндпоинты на 127.0.0.1, модели в ростере.
  Это замена сетевой охраны (принцип 5 architecture.md; NFR-2.4/2.5).
- БД: SQLite в тестах и dev, PostgreSQL на прогонах — через SQLAlchemy
  (`lab.db`); сеть не охраняется, проверки номинальные.
