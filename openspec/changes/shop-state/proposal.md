## Why

СС нужен внутренний журнал событий и затрат: без него не собрать честный
учёт по сторонам (клиент/защита/атакующий), не проверить воспроизводимость
траектории и не получить сырьё для метрик. Переносится единый журнал
прототипа (`event_log`, #32) поверх хеш-цепочки `lab.chain` — append-only
по построению.

## What Changes

- `services/shop/journal/log.py` — `EventLog` (журнал одного прогона) и
  `ComponentWriter` (компонент пишет только через выданный writer);
- `services/shop/journal/schema.py` — реестр компонент/сторон/видов событий,
  валидация payload и затрат;
- `services/shop/journal/costs.py` — по-сторонний учёт затрат;
- эпизоды открывает/закрывает оркестратор (`start_episode`/`end_episode`);
- sink журнала — JSONL на хеш-цепочке `lab.chain`.
