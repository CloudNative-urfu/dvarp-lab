## MODIFIED Requirements

### Requirement: Tactics registry from frozen corpus
Реестр методов давления SHALL быть заморожен в `frozen/corpus/tactics.json`;
метод для эпизода назначается планом прогона, а не выбирается моделью;
неизвестный метод — ошибка. Метод задаёт, КАК давить (путь давления в
system-промпте), и не содержит данных претензии; реплики корпуса не
используются как обязательные диалоги — стартовая реплика атакующего
определяется целью. Рандом-плейсхолдеры (`ORD-{random}` и т.п.) исключены:
промпт атакующего — детерминированная функция «цель × метод × тон», сида не
зависит.

#### Scenario: Method by plan
- **WHEN** эпизод атаки запрошен с методом из реестра
- **THEN** описание метода входит в system-промпт атакующего

#### Scenario: Prompt is seed-independent
- **WHEN** один и тот же «цель × метод × тон» запрошен с разными сидами
- **THEN** system-промпт и стартовая реплика совпадают байт в байт

### Requirement: Shared pair style in attacker prompt
Стиль общения пары SHALL задаваться в обеих ногах: легальному клиенту —
стиль из `frozen/styles.json`, атакующему — тон-клауза в system-промпте при
сохранении замороженной претензии (метод — как давить, цель — что требовать,
стиль — тон). Записи filter пинят `raw.style`; иначе тон становится
конфаундом детекции (инвариант 8).

#### Scenario: Style in both legs
- **WHEN** пара прогонов ведётся в стиле s
- **THEN** легальная нога и атакующий промпт несут один и тот же тон;
  претензия цели не меняется

#### Scenario: Style pinned in raw
- **WHEN** атакующий эпизод пишет сырьё
- **THEN** записи содержат `raw.style` = стиль пары

## ADDED Requirements

### Requirement: Attacker goal axis
Ось целей SHALL быть заморожена в `frozen/corpus/goals.json` (схема
`dvarp.goals/1`): каждая цель — ключ + вектор преувеличения + ссылка на
заказ мира (клиент A) или на фиктивный заказ из манифеста мира; по одной
цели на каждый тип преувеличения (несуществующий заказ, final_sale, сумма
выше цены, подмена товара, истёкший срок, завышенное количество, форсированная
эскалация). Конкретные данные претензии SHALL собираться attack-сервисом из
манифеста мира и входить в system-промпт как есть — ничего не генерируется.
shop SHALL отдавать атакующему только диалоговую поверхность /turn (брифа
атакующего нет). Записи filter пинят `raw.goal`.

#### Scenario: Claim bound to world data
- **WHEN** атакующий эпизод запущен с целью из реестра
- **THEN** претензия в промпте содержит факты заказа манифеста мира (или
  фиктивного заказа) без генерации

#### Scenario: No attacker brief from shop
- **WHEN** атакующий эпизод ведётся
- **THEN** attack_svc обращается к shop только через /turn; бриф-эндпоинта нет

#### Scenario: Goal pinned in raw
- **WHEN** атакующий эпизод пишет сырьё
- **THEN** записи содержат `raw.goal` = ключ цели
