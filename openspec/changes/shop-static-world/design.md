## Context

Ишью dvarp-lab#6: один статический мир БД вместо перебора миров-сидов.
Прежняя механика (`db.generate(seed, ShopParams)`): n_legal/n_attacker клиентов,
по 6 заказов-архетипов каждому, роли в `accounts_manifest` внутри meta БД,
легальный кейс — случайный заказ от сида, причина возврата — `rng.choice` от
сида (`traffic/case.py`), стартовая реплика атакующего — случайная запись
корпуса с рандомными плейсхолдерами `ORD-{random}` (`attack/tactics.py`).
Для оси целей (#4) нужна привязка «претензия → конкретные данные БД», которой
в сид-мирах взять неоткуда.

## Goals / Non-Goals

Goals:

- один замороженный мир в `frozen/seed_worlds/world_a/`: клиент A, 9 заказов,
  покрывающих все векторы (возвратный / final_sale / дорогой / дешёвый
  многопозиционный / древний с истёкшим сроком / уже возвращённые с разными
  причинами / недоставленный), фиктивный заказ в манифесте;
- БД внутри мира не зависит от сида: тот же мир → байт-идентичная БД; время
  симуляции — константа мира;
- роли (legal/attack) и фиктивный заказ — в манифесте мира (файл), в БД не
  остаётся ни одного следа роли/атакующего;
- легальный эпизод — один фиксированный всегда-возвратный заказ; ось стиля —
  единственная ось легальной ноги;
- атакующий кейс определяется целью; промпт атакующего собирается attack-сервисом
  из «цель × метод × тон» без обращений к shop и без генерации фактов.

Non-Goals:

- реестр ~70 методов (#4) — отдельная задача; здесь методами остаётся
  `tactics.json` (ось tactic), но без рандом-плейсхолдеров и без выбора реплики
  корпуса от сида;
- структурный stop/verdict (#10, #15) — не трогается;
- офлайн-путь evaluator/guard-plugins (`EpisodeStateManager` + seed-генератор)
  сохраняется: корпусу v2 нужны пары актор/жертва из нескольких аккаунтов;
  его ревизия — в #4.

## Decisions

- **Формат мира** (структура каталога — решение исполнителя):
  `frozen/seed_worlds/world_a/{manifest.json, customers.csv, orders.csv,
  order_items.csv, refund_history.csv}`. CSV валидируется в стиле существующих
  `_load_csv_*` (заголовок, словари статусов/причин, ASCII-английский,
  ссылки целостны). `dataset_hash` = `lab.repro.hash_tree(world_dir)` — пин
  версии замороженного мира; он же пишется в meta БД.
- **Без каталога SKU**: отдельной таблицы SKU нет; факты товара (наименование,
  цена, final_sale, причина возврата) живут в строках `order_items` (новая
  колонка `reason_code`, SCHEMA_VERSION 4). Срок возврата вычислим из
  `delivered_at` заказа и константы `now` (правило R1 — 30 дней, policy в БД).
- **Манифест мира** (`manifest.json`, не в БД): привязка клиента → роли →
  заказы, фиктивный заказ (полные факты — его в БД нет), легальный кейс
  (заказ + позиция), константа `now`. `shop_svc` читает манифест при /reset
  и при open эпизода; `traffic_svc` берёт фиксированный кейс; `attack_svc`
  собирает факты претензии из манифеста. Все три сервиса читают один и тот же
  файл через `lab/world.py` — единственный загрузчик манифеста.
- **Цели** (`frozen/corpus/goals.json`, схема `dvarp.goals/1`): 7 целей — по
  одной на тип преувеличения (refund_nonexistent → фиктивный заказ,
  refund_final_sale, refund_overprice, refund_wrong_item, refund_expired,
  refund_quantity, escalate_confused). Цель = ключ + вектор + ссылка на заказ
  мира + замороженная претензия (шаблон с плейсхолдерами фактов). Плейсхолдеры
  заполняются из манифеста механически — без рандома и без LLM.
- **Промпт атакующего** — детерминированная функция «цель × метод × тон»:
  претензия (рендер шаблона цели фактами манифеста) + описание метода + тон
  стиля. Стартовая реплика = отрендеренная претензия (у stub-атакующего она же
  — весь диалог давит фразами). `resolve_placeholders`/`start_prompt` с
  рандомом удаляются; выбор записи корпуса от сида выпадает.
- **`/turn` получает `goal`** (опциональное поле запроса): при открытии
  attack-эпизода shop привязывает тикет к заказу цели (фиктивный → тикет без
  заказа). Метаданные маршрутизации — не утечка барьера: ответ /turn по-прежнему
  ровно `{text, ended, session_status}`.
- **meta БД**: ключи `world` и `dataset_hash`; ключи `seed` и
  `accounts_manifest` больше не пишутся (seed — свойство прогона: журнал,
  манифест launcher'а; роли — свойство манифеста мира). Снапшот пары — от мира
  (снимок после reset до эпизодов), как и прежде.

## Risks / Trade-offs

- Две ветки сидирования (мир для live, сид-генератор для офлайн-evaluator) —
  осознанно: corpus v2 требует пар актор/жертва; объединение — в ревизии #4.
- `order_items.reason_code` — семантика «причина, которую назовёт клиент»:
  замороженная правда кейса (#15), не истина о товаре.
- goals.json появляется до реестра методов #4 — цели уже заморожены в #4
  (стартовый список), мир обязан ссылаться на них; правки целей при ревизии #4
  — осознанный коммит по frozen-дисциплине.
