## ADDED Requirements

### Requirement: Guard plugin contract
Стек защиты SHALL переноситься из dvarp-prototype @ `d5828df` с единым
контрактом плагина (FR-1.5): вход с контекстом и происхождением (FR-1.6),
сигнал и запись затрат (FR-1.7), пассивность — запрет менять БД и принимать
бизнес-решения (FR-1.8). Реестр плагинов задаёт набор по конфигурации.

#### Scenario: Passive guardrails
- **WHEN** плагин обрабатывает вызов
- **THEN** он возвращает только сигнал; БД и бизнес-решения недоступны (FR-1.8)

#### Scenario: Context provenance on input
- **WHEN** плагин получает вход
- **THEN** вход несёт контекст и происхождение фрагмента (FR-1.6)

### Requirement: Executor security boundary
Исполнитель SHALL быть границей безопасности (FR-1.13): его проверки
(права по роли, инструмент завершения — ровно один на обращение) одинаковы
во всех конфигурациях и не зависят от гвардрейлов (FR-1.14). Агент не может
выдать своё решение мимо границ.

#### Scenario: Boundary invariant across configs
- **WHEN** одна и та же последовательность вызовов повторяется на g0 и
  guarded-конфигурации
- **THEN** граница исполнителя отрабатывает одинаково (FR-1.14)

### Requirement: Policy pipeline over the agent channel
Политика SHALL перехватывать канал агента (обёртка GuardedDefender) и
применять реакции конфигурации — isolate / escalate / terminate; реакции
компоненты policy фиксируются в журнале по стороне защиты. Код агента
о гвардрейлах не знает (FR-1.9); самолимит гвардов не на счёт атакующего
(NFR-2.9).

#### Scenario: Agent unaware of guards
- **WHEN** тот же код агента работает на g0 и на guarded-конфигурации
- **THEN** код агента не меняется — перехват только через конвейер (FR-1.9)

#### Scenario: Reaction by config
- **WHEN** гвардрейл даёт сигнал
- **THEN** политика применяет реакцию конфигурации и записывает её в журнал

### Requirement: Five agent tools
Инструменты агента SHALL соответствовать пяти инструментам канона
(FR-1.11): specs описывают права по ролям, toolbox исполняет вызовы через
границу исполнителя; завершающая операция — ровно одна на обращение.

#### Scenario: Tools through the boundary
- **WHEN** агент вызывает инструмент
- **THEN** вызов проходит проверку прав по роли (FR-1.13/1.14)

### Requirement: Local LLM client
LLM-клиент SHALL работать в локальном контуре (NFR-2.5): settings с
закреплённой версией, backends (stub по умолчанию, локальный OpenAI-
совместимый), limits и usage_estimate (NFR-2.6: модели ≤ 8B); ключи —
только в env процесса, в журнал и манифесты не попадают.

#### Scenario: Local endpoints only
- **WHEN** клиент настроен по умолчанию
- **THEN** эндпоинты на 127.0.0.1, ключи не попадают в журнал

### Requirement: Manual review queue
Очередь ручных разборов SHALL переноситься по ревизии канона (FR-1.15/1.16,
dvarp#18): аналитическая модель вместо DES в измерительном пути (NFR-2.8),
эскалация наполняет очередь, разборы не блокируют ход эпизода.

#### Scenario: Escalations land in queue
- **WHEN** агент эскалирует обращение
- **THEN** кейс попадает в очередь ручных разборов, эпизод продолжается

### Requirement: Agent channel layer
Канальный слой SHALL отделять легального пользователя (legal_user),
LLM-пользователя (llm_user) и контракт заявок (proposal_contract) от
внутренней механики; наружу канал отдаёт только текст.

#### Scenario: Channel text-only
- **WHEN** пользователь канала получает ответ
- **THEN** ответ — только текст, без внутренних структур

## ADDED Requirements

### Requirement: Refund support agent over the LLM client
Агент поддержки возвратов SHALL переноситься из прототипа поверх LLM-клиента
(FR-1.10): системный промпт — английский, описывает бизнес-процесс возвратов
и порядок работы с пятью инструментами, не упоминает гвардрейлы
(FR-1.9, NFR-2.7); действия — свободный текст плюс структурированные вызовы
инструментов (FR-1.12); клиенту агента ответы нейтральны и не раскрывают
внутренних причин (лимит, сбой модели — NFR-2.7, FR-1.3).

#### Scenario: Agent knows no guards
- **WHEN** пакет агента проверяется на зависимости
- **THEN** ни код, ни промпт, ни параметры не ссылаются на гвардрейлы (FR-1.9)

#### Scenario: English neutral replies
- **WHEN** агент отвечает клиенту
- **THEN** ответ — английский нейтральный текст без внутренних кодов и JSON
  (NFR-2.7)

### Requirement: Deterministic agent stub
Stub-агент SHALL обеспечивать детерминизм dev-прогонов: без модели тот же
эпизод воспроизводится побайтно (NFR-2.2), реплики чередуются по паттернам
корпуса.

#### Scenario: Byte-identical replay
- **WHEN** эпизод с stub-агентом повторяется с тем же сидом
- **THEN** траектория совпадает побайтно (NFR-2.2)
