## Context

Перенос защиты из dvarp-prototype @ `d5828df` без изменения поведения:
адаптируются только импорты, каналы и порт-клей (lab-нейминги, `lab.chain`
вместо локальной копии). Код защиты в прототипе доработан до среза `d5828df`
(canon #32: конфиг-матрица, корпус v2, аналитическая очередь) — переносится
именно этот срез.

## Goals / Non-Goals

Goals:

- контракт плагинов (FR-1.5) с входом «контекст + происхождение» (FR-1.6),
  сигналом и записью затрат (FR-1.7) и пассивностью (FR-1.8: гвардрейлы не
  пишут в БД и не принимают бизнес-решений);
- исполнитель как граница безопасности (FR-1.13): его проверки одинаковы во
  всех конфигурациях и не зависят от гвардрейлов (FR-1.14);
- конвейер политики: перехват вызовов агента, реакции isolate/escalate/
  terminate по конфигу;
- пять инструментов агента (FR-1.11) с правами по роли;
- LLM-клиент локального контура (NFR-2.5) с лимитами и учётом использования
  (NFR-2.6: ≤ 8B, исключения по спеке);
- очередь ручных разборов по ревизии канона (FR-1.15/1.16, DES вне
  измерительного пути, NFR-2.8).

Non-Goals:

- сетевая изоляция процессов — заменена номинальной проверкой (lab.nominal);
- перенос isolation/svckit/state_store/pay_emu/freeze из прототипа.

## Decisions

- Перехват агента — через конвейер `GuardedDefender`: код агента не знает о
  гвардрейлах (FR-1.9), обёртка ставится снаружи (factory).
- OSS-детекторы (oss_deberta, адаптеры каталога §16, NFR-2.4) выключены по
  умолчанию; правила и textnorm работают всегда.
- Затраты записываются в журнал (shop-state) по сторонам: самолимит гвардов
  не на счёт атакующего (NFR-2.9).
