# Design — queue-scenario

## Модель (issue #12, канон dvarp#39)

```
доля_эскалаций_магазина = p_att·E_A + (1 − p_att)·E_L     ← ревейт с лаб-микса
λ_чел = ρ₀·K·60/S      (поток «сразу в очередь»: минимум 30% обращений, ρ₀ = 0.3)
λ_ИИ  = λ_чел·(1−h)/h  (остальной поток обрабатывает ИИ; h = 0.3 из пина)
λ_Q = λ_ИИ·доля_эскалаций;  λ = λ_чел + λ_Q                 ← дренаж от суммарного
a = λ·S/60;  ρ = a/K;  P_wait = Эрланг C(K, a)              ← рекурсия Эрланга B
W_q = P_wait·60/(K·60/S − λ);  P_abandon = P_wait·e^(−(K·60/S − λ)·τ/60)
член ΔNet: churn = Δ(w_L·E_L·P_abandon)·C_churn
```

Семантика базы (владелец, 2026-11-24): «минимум 30% обращений идут сразу
в живую очередь» — константа, не зависящая от защиты; эскалации приходят
только из ИИ-канала. Отличия от прототипа (`analytic.py`): базовая
нагрузка ρ₀ = 0.3 существует (в прототипе очередь питалась только
эскалациями, поэтому дренаж считался от `K·μ − λ_Q`; здесь корректно от
суммарного λ), отвал моделируется, сценарий задаётся пином экономики.
Следствие семантики: защита может реально донашивать очередь —
насыщение (ρ = 1) при ~100% отрейтченных эскалаций; отвал ≈ 14% на
эскалированный тикет при esc_share ≈ 0.7, ≈ 54% при 0.9.

## Цена ухода — через Prices, а не через extract

`ql_abandon` — чистая вероятность (w_L·E_L·P_abandon); деньги применяет
`Prices.C_churn` (10/20/40, base 20 из пина) — так цена ухода попадает под
стандартную чувствительность ±×2 вместе с C_refuse/C_manual («L* на
границах диапазонов» сохраняется). Атакующий, уйдя из очереди, бизнесу не
вредит — член ведёт только по легальным эскалациям.

## Экономика члена в реалистичном диапазоне

При ρ₀ = 0.3 и терпении 4/5 мин очередь поглощает эскалации почти даром:
даже при esc_share = 1 (ρ ≈ 0.6) отвал ≈ 1.8% на эскалированный тикет.
Вывод «в здоровом магазине защита не донашивает очередь до оттока» —
численный след сценария; порог вреда (ρ₀ ≥ 0.6) — чувствительность.

## Non-claims

- очереди — модель, а не живой оператор;
- цена минуты ожидания (C_queue прототипа) не заявлена в пине — член
  `ΔQ·C_queue` не возвращается; задержка `Q_L = E_L·W_q` публикуется
  временем (строка `queue_q_l_min`);
- дискретно-событийная симуляция отсутствует (в отличие от прототипа —
  там DES оставался как проверка формулы).
