## Why

Queue-члены формулы L* (`ΔQ·C_queue`, `ΔP_sla·C_sla`) выкинуты при переносе
(`formulas.py`: «Q = P_sla = 0 for every config») — расходная сторона не видит
перегрузку операторов от эскалаций. В прототипе это `manual_queue/analytic.py`;
владелец 2026-11-24 зафиксировал сценарий очереди (issue #12) и ревизовал
канон (dvarp#39, canon-request 001): отвал клиентов возвращён в аналитическую
модель, чувствительность ρ₀×p_att, ревейт долей эскалаций на реалистичный микс.

## What Changes

- `services/metrics/queue.py` — аналитическая очередь: Эрланг C рекурсией
  Эрланга B (санити прототипа `erlang_c(2,1)=1/3`, `erlang_c(3,2)=4/9`),
  сценарий ρ₀=0.3 (база от «сами требуют человекка»), ревейт
  `p_att·E_A + (1−p_att)·E_L`, якорь 7 операторов / 5 мин / 4 мин терпения,
  отвал = `P_wait·exp(−drain·τ)`; без симуляции, полностью post-hoc;
- `frozen/economics.json` — секция `queue` (якорь масштаба: base_rho/operators/
  service/patience);
- `services/metrics/extract.py` — доли эскалаций раздельно (E_A/E_L),
  член `ql_abandon = w_L·E_L·P_abandon` (без цены);
- `services/metrics/formulas.py` — член `churn = Δql_abandon·C_churn`
  в числителе L*; цена C_churn (10, 20, 40) под чувствительность ±×2;
  `ΔQ·C_queue` — non-claim (цена минуты ожидания не заявлена, задержка
  публикуется временем), SLA = терпение (один порог);
- `services/metrics/app.py` — строки `E_attack`, `E_legal`, `queue_*`.

## Capabilities

### Modified Capabilities
- `metrics-svc`: queue-член L* рассчитывается аналитической моделью
  (Эрланг C) из сохранённых финалов по пину экономики; правка параметров
  меняет числа без перезапуска прогонов.

## Impact

- Никакой симуляции в рантайме; сбор не меняется (сбор ≠ расчёт);
- канон уже ревизован (dvarp#39) — расхождений нет;
- golden-метрики без эскалаций не меняются (ql_abandon = 0).
