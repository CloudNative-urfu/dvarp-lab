## Why

Экономические метрики канона (FR-1.23 «стоимость вычислений в деньгах»)
сейчас не реализованы: `formulas.py` пинит `C_ep=0` и `C_guard=0` — расходная
сторона L* нулевая. Данные уже собираются (журнал `llm_call` с
`cost{tokens_in, tokens_out, requests, latency_ms}`; затраты гвардов в
записях сигналов) — задача их расчехлить post-hoc (issue #11). Владелец
2026-11-24 зафиксировал экономический пин (frozen/economics.json) и
ревизовал базовую цену ручной проверки (C_human = $2 = C_manual base).

## What Changes

- `frozen/economics.json` — замороженный пин экономики: тарифы агента
  (0.50/1.50 USD за 1M in/out), тарифы гвардов (0.15/0.15), C_human=2,
  C_churn=20, сценарии p_att {1,3,10}%, факторы чувствительности;
  не-LLM гварды — строго $0 (CPU-секунды остаются временем);
- `services/metrics/economics.py` — валидирующий загрузчик пина;
- `services/metrics/extract.py` — пост-хок разбор `raw.events`:
  agent `llm_call` → C_ep, `guard:*` сигналы/ошибки → C_guard
  (раздельно; NFR-2.9 — затраты атакующего исключены);
- `services/metrics/formulas.py` — C_ep/C_guard из агрегатов (пины 0.0
  убраны), базовая цена C_manual = пиновый C_human $2, диапазон §9.4
  расширен до (1, 2, 15); queue-члены по-прежнему нули (issue #12);
- `services/metrics/app.py` — строки `C_ep`, `C_guard`, `C_guard_cpu_ms`
  в выдаче метрик;
- тесты: golden под новый пин (C_manual=2), cost-тесты (end-to-end
  затраты → L*), пин-валидация.

## Capabilities

### Modified Capabilities
- `metrics-svc`: стоимость защитной стороны (C_ep/C_guard) рассчитывается
  post-hoc из сохранённых журналов по замороженному пину экономики.

## Impact

- Сырая БД и сбор не меняются (сбор ≠ расчёт);
- L* с ненулевой расходной стороной; golden-значения метрик меняются
  (C_manual base 6 → 2) — обновлены;
- канон не правится: значения цен лаба объявляет сама (FR-1.23),
  расхождений с FR-1.x/NFR-2.x нет.
