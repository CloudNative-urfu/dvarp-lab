## Context

Срез кода — `main@fdcf6f8`, дата сверки 27.11.2026. Проверяются именно исходники
этой ревизии, а не прежние номера строк из API-обзора. Текущие README относятся
к фактической реализации; более сильные требования не выдаются за готовые гарантии.

## Decisions

1. Единый порядок: назначение → вход/выход HTTP (для библиотек — функции) →
   хранилища/схемы → поля/метрики → инварианты/ограничения → карта кода → проверка.
2. Ссылки относительные, с `#L<номер>` и именем функции в подписи. Они открывают код
   в GitHub и проверяются на наличие файла и допустимый номер строки. Версия
   среза в каждом README позволяет отличать факт от последующего дрейфа.
3. Не добавлять README внутрь world_a: hash_tree учитывает состав каталога и такое
   добавление изменило бы dataset_hash. Карта всех frozen-данных находится выше.
4. Девять модулей публикуются отдельными PR. Общий change растёт вместе с ними;
   tasks каждого PR содержит только проверенные изменения соответствующего блока.
   Корневой индекс публикуется после наличия целевых README, без битых ссылок.
5. Отчёт аудита — свидетельство проверки конкретной ревизии. Документация не закрывает
   findings и не заменяет повторную приёмку после исправлений. Новые наблюдения по
   коду помечаются как наблюдения, не приписываются автору аудита.

Дополнительные наблюдения при чтении кода, не новые выводы аудита:

- Outbox shop хранится в памяти; общей транзакции SQL/chain/cassette у filter нет.
- В metrics есть помощник queue_grid, но aggregate не передаёт его результат в
  Aggregate; выдаваемая queue_grid остаётся default `{}` на этом срезе.
- attack-LLM теперь генерирует старт по методу; старый docstring episode.py и
  формулировка инварианта 8 о корпусном старте отстают от attacker.opening и API.
- Traffic выполняет только SELECT, но не устанавливает SQLite mode=ro на своём engine.
- Probe отбрасывается в extract по флагу отдельной raw-строки, тогда как shop
  не получает и не пишет этот флаг. Исключение всей ноги защитника не гарантировано;
  это отдельно отмечено в attack/launcher/metrics, без изменения кода.

Код findings в этой задаче не исправляется. Перед последним PR нужно сверить,
не появился ли новый отчёт #43/новый main; приложить его к итоговой сверке и обновить
изменившиеся факты. Закрытие #43 не является побочным действием docs-PR.

на уже существующие API/исходники, чтобы каждый промежуточный PR оставался целостным.

## Validation

Проверки документации: все относительные ссылки и номера строк; полнота списка
metric_results по _metric_rows; соответствие HTTP-таблиц реальным обработчикам;
допустимость упомянутых команд, git diff --check, openspec validate --all.
Новых тестов или CI-гейтов для текста не добавляется. Выполнение тестовых команд
подтверждает инструкции, но само по себе не закрывает findings аудита.
