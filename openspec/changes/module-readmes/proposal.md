## Why

Issue: https://github.com/CloudNative-urfu/dvarp-lab/issues/44

Исследователь должен понимать поток «сбор → сырьё → расчёт», схемы и ограничения
без чтения реализации. Высокоуровневая архитектура и перечень API этого не заменяют.

## What Changes

- Первый блок серии: README shop с конвейером хода, схемами, журналом,
  truth/verdict, доставкой, финалами, канарейкой и снимками.
- Общий шаблон, ссылки на исходники и номера строк, команды проверки магазина.
- В docs/agent-manual.md — обязательное обновление README в PR, меняющем модуль.
- Сверка с доступными отчётами аудита #43 без объявления его принятым.
- Следующие блоки: filter, metrics, traffic, attack, lab, frozen, launcher, ui;
  корневой индекс добавляется в конце серии. В issue перечислены девять модулей,
  хотя вводная строка говорит о семи; план охватывает все перечисленные пути.

## Capabilities

### New Capabilities
- `module-docs`: документация крупного модуля для исследования по единому шаблону.

### Modified Capabilities
- Нет: код, API, схемы БД, frozen-пины и постановка исследования не меняются.

## Impact

Только документация и OpenSpec. Работа публикуется по одному модулю на PR;
первый (shop) включает правило антирота и основу change, последний — корневой индекс
и итоговую сверку с доступным отчётом #43. Этот блок не завершает issue #44
и не публикует заранее подготовленные README остальных модулей.
