## Компоненты

| Компонент | Роль | Эндпоинты |
| --- | --- | --- |
| `shop_svc` | БД магазина (замороженный мир `frozen/seed_worlds/world_a` — один клиент, 9 заказов, роли в манифесте мира вне БД) + процесс возврата с ИИ-агентом: гвардрейлы (и их пассивность), политика реакций, инструменты агента, права исполнителя, правила эскалации, внутренний журнал | `/reset`, `/snapshot`, `/snapshot/{id}`, `/turn`, `/configure` |
| `traffic_svc` | Симуляция безопасного трафика: фиксированный правдивый возврат (всегда-возвратный заказ мира, причина — из БД), стили общения (заморожены) | `/run-episode` |
| `attack_svc` | Симуляция атаки: цели — замороженные претензии поверх данных мира, методы давления (заморожены); промпт атакующего собирается сам, без брифа от shop; ходит только текстом; сигналы начала/конца атаки | `/run-episode`, `/start`, `/stop` |
| `filter_svc` | Фильтрация: разделение ответа и сырых внутренних данных; наружу — только текст; сырьё + снимки состояния + кассеты пишет в свою БД (хеш-цепочка) | `/record`, `/text/{episode}`, `/chain/verify` |
| `metrics_svc` | Расчёт метрик (L* и формулы канона) поверх сырой БД — запускается в любое время, результаты в своей БД, агрегация по config × model | `/compute`, `/metrics/{config}` |
| `launcher` | Скриптовый оркестратор: перебор сетки «модель × конфигурация × сценарии взаимодействия», выбор конфига + seed, сброс БД магазина, номинальные проверки, парные прогоны, триггер расчёта метрик | CLI |
| `ui_svc` | Консоль полигона (9410): формы запуска осей, прогресс, эпизоды, метрики, история, система — только читатель/вызыватель | `/api/*` |

## Потоки данных

1. `launcher`: выбирает конфиг + цель + сид → номинальная проверка → сброс БД
   магазина к замороженному миру (пин world/dataset_hash) → парные прогоны
   (легальный + атакующий трафик на одном конфиге) → при желании триггерит
   расчёт метрик (может быть запущен в любое время).
2. `traffic_svc` читает БД магазина для правдивого запроса на возврат
   (фиксированный кейс мира); диалог идёт «только текст ответа» через
   `filter_svc`.
3. `attack_svc` собирает промпт атакующего из цели (претензия), метода (путь
   давления) и тона оси стиля; без доступа к защите и БД магазина; наружу —
   только текст.
4. `shop_svc` пишет в БД магазина («запись о возврате», «чтение для проверки
   реальности возврата») и отдаёт `filter_svc` «текст + снимок состояния»;
   роли (legal/attack) живут в манифесте мира — файла, не в БД.
5. `filter_svc` сохраняет «данные для расчёта» и «снимок состояния» в свою БД,
   возвращает симуляциям только текст.
6. `metrics_svc` считает L* и сохраняет «L* для конфига» в свою БД.

## Замороженные характеристики (frozen/)

- `configs/*.json` — конфигурации защиты (из прототипа @ d5828df);
- `llm.json` — ростер моделей (имя, размер, версия весов); меняется редко и осознанно;
- `seed_worlds/world_a/` — единственный статический мир БД: клиент A, 9 заказов
  без каталога SKU, история возвратов; манифест мира (роли, легальный кейс,
  фиктивный заказ) — файл вне БД;
- `corpus/` — методы атаки (`tactics.json`), цели (замороженные претензии
  `goals.json`), пиннутый корпус записей;
- `styles.json` — общий реестр ролей общения обеих ног пары: 20 новых и 3 прежних
  стиля. Описание и примеры задают тон в system-промптах legal/attack; банки
  stub-ответов опциональны, без них используется нейтральный набор.

## Принципы

1. **Сбор ≠ расчёт.** В процессе прогона только сбор сырых данных. Метрики —
   отдельным сервисом, когда угодно, поверх сохранённого; правка формул не требует
   перезапуска прогонов.
2. **Пин модели.** Каждый прогон и каждое хранилище (журнал shop, запись attack,
   сырьё filter, агрегаты metrics, манифест launcher) фиксируют `model_spec`
   (агент поддержки и атакующий — раздельно).
3. **Seeds.** Детерминированные части прогона (раскладка реплик, заглушки) — от
   seed; данные магазина — замороженный мир (один и тот же для любого сида);
   живая модель недетерминирована — реален трейс (сырые транскрипты).
4. **Журнал — хеш-цепочка** (JSONL, seq/prev/hash). **Кассеты** — по строке на пару
   запрос→ответ к модели.
5. **Сеть без охраны.** Вместо сетевой изоляции — номинальная проверка конфигурации
   перед каждым прогоном (см. `lab/nominal.py`).
6. **Сервисы для читаемости.** Код повторяет схему 1:1; обмен — HTTP на локальных
   портах; PostgreSQL (запуски) / SQLite (тесты) через SQLAlchemy.
