# AGENTS.md — правила работы для ИИ-агентов в dvarp-lab

Проект: **dvarp-lab** — полигон проверки гипотез исследования (статья, USBEREIT/IEEE):
защита СС «магазин возвратов» под легальным и атакующим трафиком, сырые данные,
метрики канона. Репозиторий — единственный, код защиты перенесён из
dvarp-prototype @ `d5828df`.

## Контекст: читать в этом порядке

1. **`docs/agent-manual.md`** — критичные инварианты (барьер «только текст»,
   сбор ≠ расчёт, пин model_spec, append-only цепочки, парные прогоны, семантика
   сида), ограничения и roadmap исследования. Обязательно до любой правки кода;
2. `docs/architecture.md` — компоненты и потоки данных;
3. `docs/api.md` — контракты эндпоинтов сервисов и формат спецификации осей;
4. `docs/scheme.svg` — схема полигона;
5. `frozen/` — замороженные характеристики (конфигурации защиты, ростер моделей,
   корпус атак, стили общения). Меняются редко и осознанно.
6. `openspec/` — трейс разработки: `changes/` (дельты спек каждого содержательного
   коммита), `config.yaml` (контекст проекта, schema spec-driven).

## Запуск и проверки

```sh
uv run python scripts/dev.py     # все 6 сервисов + консоль http://127.0.0.1:9410
uv run pytest -q                 # полный тестовый набор
uv run python scripts/smoke.py   # сквозной смок (временные каталоги, гасится после)
```

## Дисциплина

- Задачи и ишью: задача ведётся в issue `CloudNative-urfu/dvarp-lab`,
  привязанном к доске **DVARP Board** (`CloudNative-urfu/projects/1`);
  коммиты — только в контексте issue; task без issue не ведётся;
- **openspec обязателен**: каждый openspec change привязан к своему issue
  (ссылка на issue в proposal). Каждое содержательное изменение коммитится
  вместе с дельтой `openspec/changes/<change-id>/` (proposal, design, tasks,
  спеки); технические правки (style, chore, мелкие docs) — отметкой в
  tasks.md своего change; изменение без дельты спеки не принимается;
- **Канон**: канон исследования — репо `CloudNative-urfu/dvarp`
  (`docs/guardrails_requirements.md`, FR-1.x/NFR-2.x). Из задач dvarp-lab
  он напрямую не редактируется; при расхождении кода лаба с каноном —
  заявка в `canon-requests/` в том же коммите + сообщение владельцу;
  правка канона — отдельный PR в `dvarp` после решения владельца;
- Коммиты: Conventional Commits **на английском**, малыми проверенными блоками,
  `git -c commit.gpgsign=false commit`;
- **Пуш — только после явной приёмки владельцем.** Без просьбы — не пушить;
- Перед коммитом: `uv run pytest` (или целевой файл); pre-commit hook
  выполняет ruff из nixpkgs (check + format) и `openspec validate --all`
  (ruff из PyPI на NixOS не стартует);
- **openspec обязателен**: каждое содержательное изменение коммитится вместе
  с дельтой `openspec/changes/<change-id>/` (proposal, design, tasks, спеки);
  технические правки (style, chore, мелкие docs) — отметкой в tasks.md
  своего change;
- Никаких Dockerfile, CI-workflow, quality-gates, мутационных скриптов —
  только код + pytest + openspec. Код читается как схема (`docs/scheme.svg`),
  лишняя обвязка запрещена;
- Секреты/`.env*` не читать; ключи LLM — только в env процесса, в журналы и
  манифесты не попадают;
- Правила командной работы, распределение задач и авторство ведутся тимлидом
  локально (`docs/governance/`, в репо не публикуются) — на исследовательские
  задачи не влияют.

## Состояние исследования

Стенд готов (сквозной смок зелёный). Live-режим ждёт локальный LLM-эндпоинт
(issue #84 в dvarp-prototype — модели desmitry/Kirill); до него все прогоны —
stub-режим. Дальнейший порядок: пилот → прегрегистрация → кампания → статья.
Модели не добавлять в `frozen/llm.json` молча — это замороженная характеристика.
